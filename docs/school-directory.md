# School directory

One `school` feature owns the state/locality directory, school records, and the
association between a school and one optional stream. Countries and levels reuse
the existing `syllabusScope` configuration. Streams remain independently managed
by the existing stream feature.

The admin page is linked from **Site Admin → School & Location Admin**:
`/features/school/pages/admin/school_admin.html`.

## Storage

All three collections use generated, stable document IDs. Names are editable
and never form part of a document path.

| Collection | Fields specific to the record |
| --- | --- |
| `schoolStates/{id}` | `country`, `name` |
| `schoolLocalities/{id}` | `country`, `stateId`, `name`, `type: "city" \| "town"` |
| `schools/{id}` | `country`, `level: "primary" \| "secondary"`, `stateId`, `localityId`, `name`, `schoolCode`, `streamId`, `searchPrefixes` |

Every record also stores `nameNormalized`, `status: "active" | "archived"`,
`version`, `createdAt`, `updatedAt`, `createdBy`, and `updatedBy`. Timestamps and
audit UIDs are generated by the backend. Timestamps are stored as Firestore
timestamps, returned as Dates from the backend module, and serialized to ISO
strings through the callable. Clients must not supply audit fields.

`schoolCode` is optional text (up to 80 characters); it is not a uniqueness
constraint. Importers should keep returned school IDs for subsequent updates.
`streamId` is either the ID of an existing stream or `null`. Stream names and year
assignments are resolved from the existing stream definition, without copying
them into school records. Each school record belongs to one level.

`searchPrefixes` is a server-generated string array on each school document. It
contains the unique, sorted 1–80-character prefixes of each word in the name.
Names use Unicode NFKC normalization and lowercase conversion; punctuation splits
words, and letters, combining marks, and numbers remain searchable. For example,
`SJKC Chung Hua` includes `c`, `ch`, `chu`, `chun`, `chung`, `h`, `hu`, and `hua`. Names retain
their existing 200-character limit. Prefix length is bounded to control document
and index size. School creates, renames, stream updates, and archives maintain
the generated field. Clients cannot supply it in write requests.

Geography is shared across levels. The UI follows country → level → state →
city/town → school; state/city menus may include locations with no schools at the
selected level. They are populated from location records, not by scanning schools.

## API entry points

Backend: `functions/features/school/school_module.js` (CommonJS).
Frontend: `public/features/school/school_module.js` (ES modules).

Both expose the following operations. Backend calls additionally take a context
as the second argument: `{auth: {uid}}`, or `{updatedBy: uid}` for trusted server
callers. Account state and administrator membership are checked using Firebase
Auth and the existing `siteAdmins` records; an input field cannot grant access.

The frontend calls the authenticated Firebase callable `schoolCatalog` in
`us-central1` with `{action: "operationName", input: {...}}`. The callable forwards
only the authenticated identity as context. This provides deployed read/write
APIs as well as reusable backend module APIs.

| API | Input |
| --- | --- |
| `getState`, `getLocality`, `getSchool` | `{id}`; module helpers also accept an ID string |
| `listStates` | `{country, status?, search?, limit?, cursor?}` |
| `listLocalities` | `{country, stateId, status?, search?, limit?, cursor?}` |
| `listSchools` | `{country, level, stateId?, localityId?, streamId?, status?, search?, searchMode?, limit?, cursor?}` |
| `listSchoolStreams` | `{country, level, limit?, cursor?}`; returns current stream headers without loading their year assignments |
| `createState` | `{country, name, status?}` |
| `createLocality` | `{country, stateId, name, type, status?}` |
| `createSchool` | `{country, level, stateId, localityId, name, schoolCode?, streamId?, status?}` |
| `updateState`, `updateLocality`, `updateSchool` | `{id, expectedVersion, ...changedFields}` |
| `archiveState`, `archiveLocality`, `archiveSchool` | `{id, expectedVersion}` |
| `assignSchoolStream` | `{id: schoolId, expectedVersion, streamId}` |
| `removeSchoolStream` | `{id: schoolId, expectedVersion}` |

Record reads return a record or `null`. Writes return the saved record, including
its ID and incremented version. Lists return `{items, nextCursor}`.
School reads and lists also return response-only `stateName` and `localityName`
labels, obtained with one batched parent-location read. These labels are not
stored on school documents and cannot be supplied in write requests.

Example:

```js
import {listSchools, getSchool, updateSchool}
  from "/features/school/school_module.js";

const page = await listSchools({
  country: "Malaysia", level: "secondary",
  stateId, localityId, search: "smk", limit: 50,
});
const school = await getSchool(page.items[0].id);
const saved = await updateSchool({
  id: school.id, expectedVersion: school.version, name: "Updated school name",
});
// Continue with the same filters and page.nextCursor when it is non-null.
```

## Permissions and validation

- Signed-in, enabled accounts may read active directory records and stream options.
- Only verified site administrators may write records or read archived records.
- `status` defaults to `active`; administrators may request `archived` or `all`.
- Directory Firestore collections reject all direct client reads/writes, including
  administrator SDK clients in the browser. All access goes through the backend.
- Country and school level must exist in `syllabusScope`. State and locality
  references must match the school's country and each other. Active records
  require active parent locations.
- A stream association must reference an existing stream with the same country
  and level. Existing student stream subscriptions are independent of school
  assignments and are not changed by these operations.
- State country and locality country/parent state are immutable. A school may
  move to another valid location through `updateSchool`.
- Every update/archive requires the record's current `expectedVersion`.
  A concurrent change returns `aborted`; reload before saving again.
- Location archival is blocked while active child localities or schools exist.
  Reference checks and writes run in a Firestore transaction, including archive
  checks against concurrent child creation. Archived records retain their IDs.
  Restore a record using its update API with `status: "active"`, after restoring
  its parent locations.

Stream definitions and country configuration retain their existing independent
management APIs. If a stream is deleted there, the admin page labels its school
association unavailable; clear it or assign a replacement before saving that
school. This feature does not cascade changes into subscriptions or syllabuses.

## Large lists and indexes

School list calls require country and level. A city/town filter additionally
requires its state. Pages default to 50 records and permit 1–100. Queries apply
filters in Firestore and sort by normalized name and document ID. Empty searches,
name-prefix searches, and single-word searches fetch at most `limit + 1` school
records to determine whether another page exists.

Opaque cursors contain the last name/ID and their query scope. Reusing a cursor
with changed filters is rejected. Cursor pages reflect current data, rather than
a frozen snapshot across later edits.

`searchMode` defaults to `namePrefix`, preserving existing name-prefix queries and
cursors. School calls can opt into `wordPrefix`, which queries `searchPrefixes`
with Firestore `array-contains`. For example:

```js
const matches = await listSchools({
  country: "Malaysia", level: "primary",
  search: "Chung", searchMode: "wordPrefix", limit: 50,
  // Optional: stateId, localityId (requires stateId), streamId.
});
```

`C`, `Chung`, `Chu`, and `Chung H` find `SJKC Chung Hua` even with both location
filters omitted. Each query word must contain 1–80 Unicode code points. Every
word is required as a prefix of a word in the school name; word order does not
matter. Repeated query words are deduplicated. Punctuation-only input and oversized
words return `invalid-argument`. Empty search returns the normal filtered list.
Word-prefix queries retain alphabetical name/ID ordering and cursor pagination;
changing the search mode, normalized query terms, or filters invalidates the
cursor. This mode does not provide arbitrary substrings or typo correction.

Firestore permits one `array-contains` condition. Multi-word searches use the
longest query word for that indexed filter and check all remaining words on the
server. Each request examines at most 200 candidates in small batches with one
lookahead record per batch. A continuation cursor records the last consumed
candidate, so pages can contain fewer than `limit` matches, including zero, while
still returning `nextCursor`. Callers must retain that continuation instead of
treating such a page as an exhausted search. Single-word queries keep the direct
indexed path. The shared picker offers **Continue searching** when needed.

School records are never downloaded wholesale for client filtering. The admin
page collects paginated location and stream lookup records only for the selected
country/state/level. The guardian school selector and school/location admin both
use the shared autocomplete with ten suggestions per page. The admin also applies
its Active, Archived, or All status filter. Choosing an admin suggestion fetches
the latest record and loads its editor; only an explicit save changes it. See
[searchable-list.md](searchable-list.md) for the generic
feature API and interaction behavior.

`firestore.indexes.json` includes the composite indexes for status, hierarchical
location, stream filtering, name ordering, and all 12 supported word-prefix
filter combinations. Firestore's local emulator does
not enforce production composite indexes; deploy these indexes before using the
new queries in production.

The tests reject nonlocal emulator addresses and non-demo project IDs before
writing. Browser tests use the real frontend wrapper, callable handler, service,
and Firestore persistence, with isolated administrator/auth transport doubles.
They cover writes, failed saves, stale versions, stream options, archives,
ten-result autocomplete pagination, first-character and multi-word search,
status/location filters, failed selection lookups, safe text, and mobile/desktop
layouts. Authorization and direct-client rules are checked separately.

Deploy the `schoolCatalog` function and new indexes, then backfill existing school
records before enabling word-prefix mode in callers. The existing directory
rules already make this a server-owned field; no rule change is required.
Upgrading from two-character word search to first-character autocomplete reuses
the same 12 indexes. Deploy the updated writer, rerun the backfill to add
one-character prefixes, and publish the updated Hosting content last.

Use the repository's configured deployment workflow:

```sh
bash scripts/deploy-firebase.sh firestore-indexes
bash scripts/deploy-firebase.sh function schoolCatalog
```

Wait for the new composite indexes to reach `READY` before enabling word-prefix
queries. The scoped function command deploys only `schoolCatalog`.

## Backfill existing search prefixes

`scripts/backfill-school-search-prefixes.cjs` previews a country/level scope by
default. It reads schools in pages, derives prefixes from their current names,
and reports already-correct, missing/stale, and invalid records. It includes
active and archived schools. Production execution is bound to the configured
`readyherox` service account and rejects emulator environment settings.

```sh
node scripts/backfill-school-search-prefixes.cjs \
  --country Malaysia --level primary \
  --report /workspace/school-imports/school-search-prefixes-preview.json

# Run after deploying the updated schoolCatalog writer:
node scripts/backfill-school-search-prefixes.cjs \
  --country Malaysia --level primary \
  --report /workspace/school-imports/school-search-prefixes-backfill.json --apply
```

Each write updates only `searchPrefixes`, leaving school IDs, names, locations,
stream associations, versions, audit fields, and student references intact. A
document-update-time precondition rejects a concurrent rename rather than writing
stale prefixes. An interruption can be resumed by rerunning: the script reads
current names and skips already-correct records. Invalid source names block the
apply phase. Completion re-reads the scope and verifies no corrections remain.
Use the backfill for existing records; the create-only Malaysia importer leaves
existing records intact and generates prefixes only for newly created schools.

## Initial Malaysia primary import

The approved June 2022 workbook contributes 7,698 schools: SK 5,868, SJKC
1,302, and SJKT 528. K9, SK KHAS, and SR SABK rows are excluded. The import
reuses existing Malaysia primary stream IDs, with 16 state/federal territory
records and 552 normalized postal-town locations. The workbook contains 575
distinct raw state/town labels; case and repeated-space variants account for
the difference. Postal locations use type `town`; the source does not supply
an official city classification. Spelling differences are retained.

`scripts/import-malaysia-primary-schools.cjs` accepts the extracted source JSON
and defaults to a read-only preview. It validates records with the school
feature's domain rules. Deterministic IDs preserve all source rows, including
the four indistinguishable pairs, and allow interrupted imports to resume.
Existing records are reused without replacement. Every create uses an
exists-false precondition, server timestamps, and version checks on its parent
locations, stream, and country configuration. Only the configured `readyherox`
service account can run the production command.

```sh
node scripts/import-malaysia-primary-schools.cjs \
  --input /workspace/school-imports/malaysia-primary-2022-source.json \
  --report /workspace/school-imports/malaysia-primary-2022-dry-run.json

# Add --apply to execute the previewed create-only import.
```

The import report records the original workbook checksum, historical snapshot
date, stream mappings, every source row's backend ID, and the duplicate review
pairs. Completion requires reading every imported record back, checking its
stored fields, and confirming that a fresh import plan creates zero records.
The source JSON and execution report are retained outside the Git repository
in `/workspace/school-imports/`. The importer has local unit and Firestore REST
emulator coverage in `scripts/import-malaysia-primary-schools.test.cjs`.
